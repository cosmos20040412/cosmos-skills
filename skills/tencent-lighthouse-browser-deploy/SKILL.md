# 腾讯云浏览器部署

把本地项目部署到用户指定的腾讯云轻量应用服务器，交付可在其他设备访问的真实网址。让应用在服务器上独立运行，关闭用户电脑不会使服务停止。

本技能提炼自一次多人网页游戏的实际部署。浏览器标签 ID、账号、域名、服务器地址、端口和目录均需在当前任务中确认，不能沿用历史值。

## 工作顺序

### 1. 确定目标和连接浏览器

- 遵从用户选择的浏览器和已有登录页面。先读取当前可用浏览器工具的使用说明，再获取标签列表和页面状态；不要假定有 Chrome、原生控制或某个固定 API。
- 有适用的连接器或用户已授权的 SSH 时优先使用；用户明确要求浏览器操作时，使用控制台提供的文件管理、自动化助手等 UI。
- 用户登录后继续工作，已有授权范围内不重复确认。需要验证码、密码或工具要求用户接管时，交给用户处理。技能本身不授予任何额外权限。
- 仅凭环境中展示的浏览器网址不能推断用户选择了该浏览器。找不到所选会话时明确说明，不静默切换到其他账号。
- 浏览器操作细节见 [控制台操作](references/browser-console.md)。该流程不要求读取 Cookie、API 密钥、SSH 私钥或云账号密码。

### 2. 先只读核对服务器

确认服务器所属账号、实例、地域、系统、配置、磁盘和公网入口；只展示与部署相关的信息。使用自动化助手读取已有软件版本、监听端口及相关网站配置。不要根据 Nginx 文件名判断域名归属，要读取实际 `server_name`、`listen` 和 `proxy_pass`。

同时检查项目说明、构建方式、后端、数据库、迁移和已有部署目录。具体检查和兼容性决策见 [准备部署包](references/prepare-release.md)。

形成简短部署记录：

| 参数 | 依据 |
| --- | --- |
| 实例、地区、系统 | 当前控制台 |
| 最终 origin 与 URL 前缀 | 已有域名、证书和用户目标 |
| 空闲本机端口 | 服务器当前监听列表 |
| 程序、数据、备份目录及服务名 | 与已有应用不冲突 |
| 运行时、启动入口、数据库方案 | 本次构建和测试结果 |
| Nginx 配置文件 | 已核实的对应域名 server 块 |
| 上传包名称与 SHA256 | 本次本地发布产物 |

若原域名已有网站，可使用独立子路径；子域名或新域名应依据现有 DNS、证书和用户选择处理。不要为复用示例强制使用子路径、SQLite 或 Node.js。

### 3. 构建、验证、上传

- 先完成可部署产物和必要配置，运行与实际改动相关的测试，再做远程安装。
- 云平台专用后端不能当作静态网页直接上传。保持游戏或业务规则，替换真正与部署环境不兼容的适配层。
- 使用明确的发布目录打包；不要上传项目根目录、开发数据库、凭据或整份用户文件夹。检查包清单并计算 SHA256。
- 通过控制台“文件管理 → 上传 → 上传文件”上传，使用浏览器当前支持的文件选择 API。以完成状态和远端校验值确认上传成功。

### 4. 安装独立服务和访问入口

按 [安装与回滚](references/service-and-rollback.md) 准备与当前服务器匹配的脚本。首次安装检测到已有目标时停止覆盖；更新则保留旧版本和数据库，设计兼容的回滚方式。

顺序为：校验发布包 → 独立目录解包 → 启动服务 → 本机健康检查 → 备份站点配置 → 添加精确路由 → `nginx -t` → reload → 公网验证。

不随意重启整台服务器、关闭其他服务、升级全局运行时、重置登录方式或放宽防火墙。需要这些变化时先确定它们确实必要，并遵守当前工具和用户授权范围。

### 5. 验证后交付

- 检查最终 HTTPS 页面、静态资源和应用 API；健康端点返回 200 不代表业务可用。
- 联机游戏使用不同会话验证创建、加入、人数限制、对局、结算、身份和手牌隔离。只创建自己的测试房间，清理也仅限本次测试数据。
- 检查子路径邀请链接、Cookie Path、Origin 校验、刷新恢复。需要验证进程重启持久化时，在隔离测试或明确不会影响用户的测试阶段进行；不能把本地验证描述成服务器重启验证。
- 通过浏览器检查真实页面显示；核对服务 active 和 enabled、原网站仍可访问。不要仅依据“命令已提交”声称上线成功。
- 将最终游戏页留作交付标签，按照工具规则清理其他临时标签。
- 用用户语言提供网址和最短使用步骤，说明应用在云服务器独立运行。保存简短维护记录：目录、服务名、数据位置、备份位置、验证结果和未完成项。没有配置异地备份时，不声称数据已有异地备份。

## 异常与边界

每次超时或报错后先观察执行结果、进程和目录状态，再决定下一步。不得盲目重复安装、上传或执行脚本。自动审核拒绝的动作不能换工具绕过；报告具体原因及需要用户完成的步骤。

配置失败只恢复本次改动的文件和路由，保留诊断信息，不删除用户数据或停掉无关服务。回滚失败或无法确认当前状态时，停止进一步修改并准确说明现状。
